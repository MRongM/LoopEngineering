# Project-level Terminal Watch Dashboard Implementation Plan

> **For agentic workers:** Execute inline in this session. Use strict RED→GREEN TDD and do not create Git commits, branches, aliases, or third-party dependencies.

**Goal:** Add `loop-engine watch` and `loop-engine watch --all` as a read-only, project-discovered terminal dashboard for Loop Runs.

**Architecture:** A new `loop_engineering.watch` module discovers the nearest configured project, builds strict read-only snapshots from `RunStore`, renders adaptive text, and owns the polling lifecycle. `cli.py` exposes one top-level human-facing command while existing `run status/events` remain machine-readable JSON interfaces.

**Tech Stack:** Python 3.12+, strict Pydantic models, argparse, standard-library ANSI/TTY handling, pytest, Ruff.

## Global Constraints

- Follow `PROTOCOL.md` 0.3.0 and the approved `docs/superpowers/specs/2026-08-01-terminal-watch-dashboard-design.md`.
- All subprocess behavior remains argv-based with `shell=False`; this feature runs no subprocesses.
- The dashboard is strictly read-only and never adopts, resumes, approves, revises, completes, or mutates a Run.
- Discover only the nearest current project and direct non-link children of its configured `.loop-runs` root.
- Do not add `loop-engine run watch`, a `run-dir` argument, or a CLI alias.
- Do not add Rich, Textual, curses, or another dependency.
- Do not commit; repository instructions require explicit user authorization for Git commits.
